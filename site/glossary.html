Reference

Glossary and quick reference

Every term used across these notes, plus the commands to reproduce each result.

Terms

TermMeaning
Action chunkA sequence of k future actions predicted in one forward pass. Here k=100, about 2 seconds at 50 Hz.
Commitment horizon (h)How many steps of a chunk are actually executed before replanning. h=100 means executing the whole chunk blind; h=20 means replanning five times as often. The quantity this project tries to control.
Open-loopExecuting without looking at new observations. A chunk executed at h=100 is open-loop for 100 steps.
Covariate shiftThe mismatch between the states a policy was trained on (the expert's) and the states it actually visits (its own). The root cause of compounding error.
Compounding errorSmall mistakes push the policy off-distribution, where it makes bigger mistakes. Grows like εT² in the horizon rather than εT.
ACTAction Chunking Transformer. A CVAE with a transformer decoder that outputs a whole chunk at once. 51.6M parameters in this checkpoint.
CVAE latent (z)A 32-d variable ACT uses during training to absorb the variability in human demonstrations. Set to zero at inference, which is why ACT is deterministic at test time.
Temporal ensemblingReplanning every step and averaging overlapping chunk predictions with exponentially decaying weights. Off throughout this project.
MC-dropoutLeaving dropout active at inference so repeated forward passes differ. v1 used it to manufacture candidate chunks from a deterministic policy.
failure_within_kv1's monitor target: "will this episode fail within k steps?" Measures proximity to termination, not recoverability.
Reversibility R(s)v2's target: the probability the task still succeeds if you replan from state s right now. Measured by snapshotting the simulator and replaying to completion 8 times.
Branch rolloutThe procedure that measures R: snapshot, restore, replan, run to the end, repeat, count successes.
Point of no returnThe first timestep after which R never again rises above 0.5. A permanent crossing — a dip the policy recovers from does not count.
Oracle conditionThe controller fed ground-truth measured R instead of a prediction. An upper bound on what gating could achieve; not itself achievable.
Out-of-fold (OOF)Scoring each episode with a model from the cross-validation fold that never trained on it. Makes the learned controller comparable to the oracle without reading its own training data.
γ (gamma)Exponent in the horizon map h = clip(h_min, 100, 100·R̂^γ). Higher γ shortens the horizon sooner as R falls.
Spearman ρRank correlation. Used because the controller only needs the ordering of states to be right.
McNemar's testA paired test that looks only at episodes where two conditions disagreed. Appropriate here because all conditions run identical episodes.
Bonferroni correctionDividing the significance threshold by the number of comparisons. With 15 pairwise tests the bar becomes p < 0.0033.

Reproducing each result

Each script is a gate: it prints GATE: PASS|FAIL, writes its evidence to artifacts/, and exits non-zero on failure.

# environment — must print PASS for every check
python scripts/00_setup_check.py --allow-no-cuda

# does our ACT match the reference implementation, seed for seed?
python scripts/01_verify_act_checkpoint.py          # → 48/50 agreement

# which disturbances actually do anything?
python scripts/03_calibrate_perturbations.py        # → 2 of 4 kinds effective

# measure reversibility (~3 hours on 3 performance cores)
python scripts/04_label_reversibility.py \
    --episodes 80 --workers 3 \
    --kinds object_displace actuation_noise \
    --shard-dir artifacts/reversibility_shards_v2

# can a model predict it?  (seconds)
python scripts/05_train_reversibility.py \
    --shards artifacts/reversibility_shards_v2      # → rho = 0.693

# does gating on it help?  (~45 min)
python scripts/06_run_ablation.py --episodes 80 --skip-gated --h-min 20 \
    --gammas 1.0 2.0 --fixed-hs 100 20 \
    --oracle-shards artifacts/reversibility_shards_v2 \
    --oof-heads artifacts/reversibility_heads_oof.pt

# the horizon sweep — the result that explains everything
python scripts/06_run_ablation.py --episodes 40 --skip-gated \
    --fixed-hs 5 10 20 40 60 80 100

python scripts/07_make_figures.py                   # figures
python scripts/08_make_videos.py --compare-fixed 5 40   # the cliff, filmed
python scripts/progress.py --shards <dir> --total 80   # watch a running job

All of this runs on a laptop CPU. MuJoCo steps at ~84/s while an ACT forward pass takes ~76 ms, so branch-rollout labelling is CPU-bound by roughly 13× and a GPU buys almost nothing. What matters is performance-core count.

Two things these notes correct

"100,000 rollouts"

The figure 100K in this project refers to ACT training steps — the step_100000 checkpoint from a training run. v1's evaluations were 20 and 10 episodes. Rollout counts in this work are in the tens, not the thousands; the largest single campaign was 158 labelled episodes.

"an entropy function"

There is no entropy term anywhere in v2. The quantity it measures is reversibility, computed by replaying the simulator from a snapshot. The distinction matters conceptually: entropy or uncertainty asks "does the policy know what to do?", while reversibility asks "does it still matter?" A state can be perfectly unambiguous and completely unrecoverable.
